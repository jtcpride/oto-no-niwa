## 0. 30秒で把握する要約

これは、英語の発音記号（IPA）を**蹴鞠の1対1ラリー**として覚える学習ゲームです。

中心ループは次です。

> **英単語を聞く → 狙った音を聞き分ける → 4つの発音記号から選ぶ → その位置へ足を運ぶ → タイミングを合わせて鞠を返す**

単なる四択クイズにしないことが重要です。知識判断（どの音か）と運動判断（いつ蹴るか）を重ね、最終的には「音を聞いたら身体が対応位置へ動く」レベルの自動化を狙います。

現行v0.9では、試合前に4音を2周するPRACTICEがあり、その後 `TIME`、見送り球、`礼`、`HAJIME!!!` を経て本戦に入ります。

## 1. プロダクトの核

### 1.1 体験仮説

説明を読ませて記号を暗記させるのではなく、

- 音
- 発音記号
- 代表語
- 画面上の位置
- 足運び
- 蹴るタイミング

を一つの体験として反復すると、発音記号が「知識」から「反応」に近づくのではないか、という仮説です。

理想的な習熟変化は以下です。

1. **think を頼る** — 「この音は think の th」
2. **/θ/ を頼る** — 記号と音が直接結びつく
3. **音だけで身体が動く** — 記号名を頭の中で言わなくても位置と蹴りが出る

### 1.2 ゲーム側の設計原理

- **1D timing × 3D spectacle**
  - ゲーム判定はシンプルなタイミング中心
  - 見た目は3D空間、足運び、球道、演出で豊かにする
- 鞠の軌道はリアル物理ではなく**演出としてスクリプト制御**する
- カメラは基本固定。必要なら軽いpush / shake程度
- 選択した発音記号によって立ち位置が変わる。v0.5以降は浅い円弧で回り込む
- 難しさをすぐ「親切」にしすぎない
  - 現在の少し理不尽な難しさが、意外に蹴鞠らしい緊張感を生んでいる

## 3. 学習設計: 4スロット方式

### 3.1 「4分類」ではなく「4音の対照セット」

英語の発音記号全体を公式に4分類する、という考え方ではありません。

代わりに、**1ステージ = 音声学的または学習上まとまりのある4音**として構成します。

現在の第1セット:

| Slot | IPA | 代表語 | 語全体IPA | 関係 |
| --- | --- | --- | --- | --- |
| 1 | `/θ/` | think | `/θɪŋk/` | 歯間・無声摩擦音 |
| 2 | `/ð/` | this | `/ðɪs/` | 歯間・有声摩擦音 |
| 3 | `/ʃ/` | ship | `/ʃɪp/` | 後部歯茎・無声摩擦音 |
| 4 | `/ʒ/` | vision | `/ˈvɪʒən/` | 後部歯茎・有声摩擦音 |

これはかなりきれいな **2×2** として読めます。

- 調音位置: 歯間 / 後部歯茎
- 有声性: 無声 / 有声

専門家が見ても「この対立を練習させたいセットだな」と理解できる構成を目標にします。

### 3.2 将来候補

きれいな対照セット候補:

- `/f/ /v/ /s/ /z/`
- `/p/ /b/ /t/ /d/`
- `/k/ /g/ /tʃ/ /dʒ/`

学習上重要だが、2×2としてはやや緩い候補:

- `/r/ /l/ /w/ /j/`

特にR/Lは日本語話者にとって重要なので、音声学的な美しさより学習価値を優先して独立セット化してもよい。

母音は子音と同じ分類原理ではなく、舌の高さ・前後など別の座標系を使う可能性があります。`/æ/` なども将来候補。

### 3.3 スロット位置の意味

通常プレイ中は4スロットの位置を固定し、身体記憶を育てます。

ただし注意点があります。

- 良い状態: 「音 → 音素カテゴリ → 対応位置」が自動化している
- 悪い状態: 「特定のTTS音声 → 左端ボタン」のような単なる刺激反応になっている

よって将来、通常プレイでは位置固定を維持しつつ、**たまに配置を変えた確認ラウンド**や、別UIでの音↔記号確認を入れて転移を検証します。常時ランダム化は身体性を壊すので避けたい。

## 4. 代表語アンカー

各発音記号に**1つの代表語**を持たせます。

例:

- `/θ/` = think
- `/ð/` = this
- `/ʃ/` = ship
- `/ʒ/` = vision

狙いは、辞書などで記号を見たときに、

> `/θ/` → 「think の th の音」

と復元できること。

実際の試作過程で、ユーザーが `/θ/` を先に覚え、「think の時の th」と結びつけられそうだという手応えが出た。これは、ゲーム内正解率だけでなく**辞書・発音学習への転移**を期待させる観察です。

将来は発音記号ごとに習熟度を持ち、代表語・発音記号を「技」のように4スロットへ装備・入替できる構想があります。

## 5. 現在のv0.9体験フロー

### 5.1 PRACTICE

4音を左から順に、**2周 = 8球**行う。

PRACTICEでは:

- CPUが代表語を読む
- 単語を画面表示
- 語全体のIPAを表示
- 狙う発音記号を表示
- 対象ボタンを強調、他の3つを薄くする
- 鞠にも正解記号を見せる
- 球速は本戦より遅め
- タイミング窓は広め
- HPは減らさない
- 本戦の正解返球数には数えない

「チュートリアル画面」ではなく、**試合前のウォームアップそのもの**として学習させるのが重要。

### 5.2 TIME

8球が終わると `TIME`。

次に飛んでくる1球は、打てるように見えるが**蹴らずに後ろへ流す**。

ここは単なるトランジションではなく、

> 「打てる。でも打たない」ことで集中に入る

ための間として扱う。

### 5.3 TIME後の選択

見送り球の後、プレイヤーは次を選べる。

- **礼**
- **もう一回練習**

「もう一回練習」はPRACTICE 8球を最初からやり直し、その後またTIMEへ戻る。

### 5.4 礼

礼は、古いゲーム的な無駄な所作へのオマージュから始まったが、結果的に本筋へ合流した。

- 礼をすると本戦開始待ちに入る
- 約2.5秒何もしなければ `HAJIME!!!`
- 待ち時間中にもう一度礼すると、また礼を行い、待ち時間が最初からリセットされる
- したがって理論上、**永遠に礼して試合を始めないことができる**

これはバグではなく意図した遊び。

意味のない所作を残しつつ、結果的には「自分で本番へ入るタイミングを作る儀式」になっている。

### 5.5 HAJIME / MATCH

礼の後、一定時間入力がなければ:

`HAJIME!!!`

その後、本戦開始。

本戦では:

- CPUが英単語を読み上げる
- incoming ball は `?`
- プレイヤーは音だけを手掛かりに4つのIPAから選ぶ
- 選択に応じて足運び・立ち位置が変わる
- 到達タイミングに合わせて蹴る

## 6. 本戦の既存ゲームメカニクス

以下はv0.3以降から継承している基礎。現在コードでも原則維持しているが、今後エージェントが触る際は実装値を確認すること。

### 6.1 蹴りの質が次の球を変える

- 早め成功 → **LOB**: 高く、遅め
- PERFECT → フラットで速い
- PERFECT連続 → 上限付きで加速 + 音演出
- 遅め成功 → **DRIVE**: 低く鋭く速い
- 救済返球 → 遅く、不格好。正解数には数えない

CPUは直前の球種を引き継ぐ設計。

### 6.2 基準値

過去仕様の基準値:

- Success window: ±180ms
- PERFECT: ±65ms
- 片道球時間: 0.70〜2.50s
- 16正解返球 または 45秒で終了
- HP 100
- ミス: -15
- HPが残る最初のミスは救済返球

PRACTICEではこれらを緩和・無効化する。

### 6.3 難しさの観察

現在の本戦はかなり難しい。ただし試遊時、

> 「蹴鞠的な理不尽さ / 難しさが絶妙」

という感触が出た。

よって、今後は単純に簡単にするのではなく、失敗を以下へ分けて観察したい。

1. **音を聞き分けられず間違えた**
2. **音は分かったが、足運び / タイミングで失敗した**

学習難度とスポーツ難度を分けて評価する。

## 7. 更新の過程

### v0.3 — 球質が次の球へ影響

- LOB / PERFECT / DRIVE
- 救済返球
- HP / miss
- 「蹴りの質が次の球を変える」

### v0.4 — 記号選択を足運びにする

- 4記号を固定位置へ配置
- 選択時に約0.3秒のstep
- 足上げ、重心沈み、上体傾き
- 連打しても位置ドリフトしない
- 学習判断には影響させず、まず視覚・身体感覚として追加

### v0.5 — 回り込み

- 直線移動ではなく浅い円弧で回り込む
- player yaw がCPUを追う
- CPUもゆっくりdepth追従
- 球の見た目にも小さくZ変化
- ユーザーから「くるっと回り込む感じ」が好感触

ここで、固定位置が「カンニング」ではなく、むしろ**身体化された音分類**として価値を持つ可能性が見えた。

### v0.6 — 「聞いて選ぶ」

- 英単語を `speechSynthesis` で読み上げ
- incoming ball は `?`
- 書かれた単語を先に見せない
- 正解時に単語・対象IPAを短く表示
- ミス時に正解IPAを表示し再読み上げ
- `🔊 もう一度`
- en-US
- 最初の4音: `/θ/ /ð/ /ʃ/ /ʒ/`

#### v0.6.1

- iPad Safariで音声が鳴らない問題に対応
- 初回ユーザータップ内でspeech synthesisをunlock

#### v0.6.2

- 初回単語が2回読まれる問題を修正

### v0.7 — 4球ならし

- ステージ冒頭4球を左から順に教示
- 正解記号を見せる
- 対象ボタンを強調
- PRACTICE中はHPや本戦カウントを守る

### v0.8 — PRACTICE 2周 / TIME / HAJIME

- 4音×2周 = 8球
- 代表語 + 語全体IPAを提示
- `/θ/` の代表語を think に寄せる
- PRACTICE終了後 `TIME`
- 1球を打たずに見送る
- `HAJIME!!!` を経て本戦へ

### v0.9 — TIME / 礼 / 再練習

- TIME後に `礼` / `もう一回練習`
- 礼後に本戦開始までの間を置く
- 待ち時間中に再度礼すれば開始タイマーをリセット
- 理論上、永遠に礼できる
- 「無駄なオマージュ」が、試合前の集中・自己決定の儀式へ発展
